# Troubleshooting

Every error leaving a jose node is a fresh `Error` with one of these codes. Catch nodes see it at `msg.error.code`; with `failureMode` set to `output`, token rejections leave verify/decrypt on the second port as `msg.error = { code, message, claim?, reason? }`. Original error text, causes and token contents are never attached. A Catch node shows the message as `Error: <message>` because Node-RED formats Error objects with `toString()`; the second output carries the bare message.

| Code                                    | Route     | Cause                                                                                                         | Check                                                                   |
| --------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `NO_KEY_CONFIG`                         | Catch     | the node has no `jose-key` selected or it was removed                                                         | pick or create a key configuration                                      |
| `KEY_UNUSABLE`                          | Catch     | key material failed to parse, is too short, is not canonical, or does not fit the operation or algorithm      | key configuration dialog; the message names the category                |
| `INVALID_INPUT`                         | Catch     | a configured option (time mode value, path, policy) or an evaluated dynamic value is invalid                  | node configuration and the TypedInput source                            |
| `INVALID_CLAIMS`                        | Catch     | claims are not a plain JSON object or cannot be serialised (function, BigInt, cycle)                          | the claims source                                                       |
| `OUTPUT_INVALID`                        | Catch     | the destination path cannot be written (scalar or frozen parent, accessor, read-only)                         | `msg` shape upstream, `tokenTo`/`claimsTo`/`headerTo`                   |
| `NODE_CLOSING`                          | Catch     | the message was in flight while the node was redeployed                                                       | expected during deploy; retry upstream                                  |
| `JWKS_FETCH`                            | Catch     | the JSON Web Key Set URL did not answer with a 200 response                                                   | URL, DNS, TLS, proxy, issuer status                                     |
| `INTERNAL_ERROR`                        | Catch     | an unexpected error; the debug log records the code and stage                                                 | enable debug logging and report the stage                               |
| `NO_TOKEN`                              | rejection | the token property is missing, empty, not a string, has an unexpected scheme, or is not compact serialisation | token source, `stripBearer`                                             |
| `INPUT_TOO_LARGE`                       | rejection | the token input is larger than 1 MiB                                                                          | upstream body limits                                                    |
| `ERR_JWT_EXPIRED`                       | rejection | `exp` is in the past (`claim: exp`) or `iat` is older than _Max age_ (`claim: iat`)                           | token lifetime, `clockTolerance`                                        |
| `ERR_JWT_CLAIM_VALIDATION_FAILED`       | rejection | a claim or `typ` did not match policy; `claim` and `reason` say which                                         | `issuer`, `audience`, `subject`, `typ`, `requiredClaims`, `maxTokenAge` |
| `ERR_JWT_INVALID`                       | rejection | the payload is not a JWT claims set                                                                           | token producer                                                          |
| `ERR_JWS_INVALID`                       | rejection | not a compact JWS (a JWE given to verify, garbage, wrong part count)                                          | token producer, node choice                                             |
| `ERR_JWS_SIGNATURE_VERIFICATION_FAILED` | rejection | signature does not match the configured key                                                                   | key, tampering                                                          |
| `ERR_JWE_INVALID`                       | rejection | not a compact JWE                                                                                             | token producer, node choice                                             |
| `ERR_JWE_DECRYPTION_FAILED`             | rejection | wrong key, tampered ciphertext or tag                                                                         | key, tampering                                                          |
| `ERR_JOSE_ALG_NOT_ALLOWED`              | rejection | the token header algorithm differs from the algorithm bound to the key configuration                          | producer and key configuration agree on the algorithm                   |
| `ERR_JOSE_NOT_SUPPORTED`                | rejection | the token uses an algorithm or header extension this package does not offer                                   | token producer                                                          |
| `ERR_JWKS_NO_MATCHING_KEY`              | rejection | no key in the set matches the token `kid`/`alg`                                                               | issuer rotation, cache age                                              |
| `ERR_JWKS_TIMEOUT`                      | Catch     | the JSON Web Key Set request exceeded `timeoutSeconds`                                                        | issuer availability, `timeoutSeconds`                                   |
| `ERR_JWKS_INVALID`                      | Catch     | the fetched set is not a valid JSON Web Key Set                                                               | issuer response                                                         |
| `ERR_JWK_INVALID`                       | Catch     | a key in the set is malformed                                                                                 | issuer response                                                         |
| `ERR_JWKS_MULTIPLE_MATCHING_KEYS`       | Catch     | several keys match; the issuer must publish distinct `kid` values                                             | issuer                                                                  |

When `OUTPUT_INVALID` reports shared-object overlap, choose destinations that do not alias each other. For example, if `msg.a` and `msg.b` refer to the same object, `a.result` and `b.result.header` overlap even though their path strings differ. Claims and headers are left unwritten.
